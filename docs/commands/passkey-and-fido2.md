# Passkey and FIDO2 command reference

These commands implement authorized Entra ID passkey sign-in and the split
Windows Hello for Business flow. See the [passkey scenario guide](../use-cases/passkey-fido2.md)
for the end-to-end diagrams and handling guidance.

## Invoke-EntraIDPasskeyLogin

Runs the software passkey flow. Use either the `Path` parameter set with
`-KeyFilePath` or the `Manual` parameter set with `-UserPrincipalName`,
`-UserHandle`, `-CredentialId`, and `-PrivateKey`.

Common optional parameters are `-RelyingParty`, `-authUrl`, `-UserAgent`, and
`-Proxy`. PowerShell 7 or later is required for ECDSA PEM support. The command
stores the resulting `ESTSAUTH` cookie and web session in global variables for
subsequent exchange.

```powershell
Invoke-EntraIDPasskeyLogin `
    -UserPrincipalName 'user@contoso.com' `
    -KeyFilePath './authorized-test.passkey'
```

## Get-EntraIDFido2Challenge

Starts a FIDO2 sign-in and returns structured flow state by default. It also saves
`$global:Fido2FlowState` and `$global:Fido2WebSession`. Use `-OutputType Challenge`
when only the challenge string is needed.

Important parameters include `-UserPrincipalName`, `-Client`, `-ClientID`, `-Tenant`,
`-Authority`, `-RedirectUrl`, `-Scope`, `-Resource`, `-AuthUrl`, `-UseV1Endpoint`,
`-UseCAE`, `-UseCodeVerifier`, `-CodeVerifier`, `-SharePointTenantName`,
`-SharePointUseAdmin`, `-UserAgent`, and `-Proxy`.

```powershell
$flow = Get-EntraIDFido2Challenge `
    -UserPrincipalName 'user@contoso.com' `
    -Client MSGraph
```

## Get-WindowsHelloFidoAssertion

Creates a signed WebAuthn assertion using the current user's Windows Hello for
Business key. `-Challenge` is mandatory. `-UserId` overrides the object ID derived
from the Windows certificate's user SID. `-RpId`, `-Origin`, and `-SignCount` are
available for controlled protocol tests. The private key remains in the Windows
key provider and is not exported by the command. TPM backing depends on the
Windows Hello for Business deployment.

```powershell
Get-WindowsHelloFidoAssertion `
    -Challenge $flow.Challenge `
    -UserId $userObjectId
```

## Invoke-EntraIDPasskeyAssertionLogin

Submits an assertion generated by `Get-WindowsHelloFidoAssertion` or another
authorized authenticator. The assertion may be an object or JSON string. Supply
`-FlowState`, or provide `-WebSession` and `-SessionInfo` explicitly.

`-OutputType Token` is the default and exchanges the resulting `ESTSAUTH` cookie
for tokens. `-OutputType ESTSAUTHCookie` returns the cookie instead. OAuth options
include `-Client`, `-ClientID`, `-Resource`, `-Scope`, `-RedirectUrl`, `-Tenant`,
`-Authority`, `-UseV1Endpoint`, `-UseCAE`, `-UseCodeVerifier`, `-CodeVerifier`,
`-UserPrincipalName`, and `-Proxy`.

```powershell
Invoke-EntraIDPasskeyAssertionLogin -FlowState $flow -Assertion $assertion
Invoke-EntraIDPasskeyAssertionLogin -FlowState $flow -Assertion $assertion -OutputType ESTSAUTHCookie
```
